# SPEC: веб-система складского учёта зеркал со сканированием и сменами

> Полная спецификация проекта. Порядок работы, этапы и правила git — в `CLAUDE.md`.
> Входные файлы лежат в `docs/input/`: `TOP.xlsx` (справочник артикулов), `Пример_этикеток.pdf` (образец этикетки), `gsheet_*.png` (скриншоты гугл-таблицы — образец вида экрана «Остатки», раздел 6.9).

## 0. Главные требования к результату

Полностью рабочий, протестированный проект без заглушек, `TODO`, `pass` вместо логики и «реализуйте сами». Запускается одной командой (`docker compose up -d`), проходит все тесты из раздела 12 и чек-лист раздела 13. Если в спецификации что-то противоречиво — выбрать разумный вариант, записать в `DECISIONS.md` и продолжать, не останавливаясь.

Запрещено: хранить состояние только в памяти процесса, считать остатки вручную вводимыми числами, удалять или редактировать записи журнала, класть секреты в код.

## 1. Цель

Система ведёт учёт **каждого зеркала** от изготовления до отгрузки, а также **учёт выхода на смену** и **ежедневные задачи** сотрудников цеха.

- Остаток по каждому артикулу и площадке всегда совпадает с тем, что физически лежит на складе.
- По любому зеркалу видно, кто и когда его сделал, где оно лежит и в какой заказ/на какую паллету ушло.
- Одно зеркало нельзя принять или отгрузить дважды.
- Видно, кто вышел на смену, а кто нет; начать смену можно только физически находясь в цеху.
- Начальник смены в конце дня ставит задачи на следующий день; сборщик, заходя в профиль, сразу видит свои задачи на сегодня и прогресс по ним.

**Не входит в первую версию:** учёт сырья и комплектующих, расчёт зарплаты, автоматический выбор, какие заказы едут (это остаётся за программой BLAGO OTGRUZKI), работа без интернета.

## 3. Основные понятия

| Понятие | Что это |
|---|---|
| Артикул | Модель товара, как в таблице TOP, напр. `Zerkalo_60x160`. 300+ позиций, импорт из `TOP.xlsx` |
| Зеркало (единица) | Один экземпляр с уникальным номером. Хранит артикул, площадку, статус, сборщика, историю |
| Площадка | Место хранения/производства: **Коминтерна**, **Учительская**. Список дополняется админом |
| Движение | Запись в журнале о любом действии с зеркалом. Не редактируется и не удаляется |
| Остаток | Количество зеркал артикула в статусе «На складе» на площадке. **Только вычисляется**, руками не вводится |
| Смена | Запись о выходе сотрудника на работу: кто, площадка, время начала, время окончания |
| Код смены | QR-код, висящий в цеху каждой площадки. Без его скана камерой начать смену нельзя |
| Задача | План на день для сотрудника: артикул × количество (для сборщика) или текстовое поручение |
| Паллета | Группа отгружаемых зеркал одного канала (Ozon / WB / СДЭК), собранная грузчиком |

### Статусы зеркала

| Статус | Когда | В остатке |
|---|---|---|
| `printed` Напечатано | Этикетка напечатана, ещё не отсканирована | Нет |
| `in_stock` На складе | Этикетка наклеена и отсканирована | **Да** |
| `in_transit` В пути | Отправлено на другую площадку, ещё не принято | Нет |
| `shipped` Отгружено | Отсканировано грузчиком на паллету / в заказ | Нет |
| `written_off` Списано | Брак, бой, потеря, ошибочная этикетка | Нет |

### Разрешённые переходы (ровно 8, всё остальное — отказ)

1. `printed → in_stock` — приёмка после изготовления
2. `printed → written_off` — испорченная/лишняя этикетка
3. `in_stock → in_transit` — отправка на другую площадку
4. `in_transit → in_stock` — приёмка на площадке-получателе
5. `in_stock → shipped` — отгрузка (скан грузчика)
6. `in_stock → written_off` — брак/бой
7. `shipped → in_stock` — возврат от покупателя (годное)
8. `shipped → written_off` — возврат от покупателя (негодное)

Исключение — исправления по итогам инвентаризации (раздел 6.6): они могут переводить зеркало в `in_stock` или `written_off` из любого статуса, кроме уже соответствующего, и всегда помечаются типом `inventory_fix`.

Таблицу переходов реализуй **одним словарём в одном модуле**; все операции проверяют переход только через него.

## 4. Роли и учётные записи

Четыре роли. Один сотрудник = одна роль. Каждое действие записывается на сотрудника, вошедшего на устройстве.

| Роль | Что может |
|---|---|
| **Администратор** | Всё, что начальник смены, плюс: сотрудники (создать, изменить роль, сбросить PIN, деактивировать), площадки, справочник артикулов (импорт TOP, добавление, деактивация), настройки этикетки, перевыпуск кодов смены, ключи API, просмотр всех отчётов |
| **Начальник смены** | Ставит задачи на следующий день и правит задачи на сегодня; видит табло «кто на смене»; печатает этикетки за любого сборщика; перемещение и приёмка между площадками; инвентаризация; списание брака; возвраты; исправление сборщика у зеркала (с записью в журнал); журнал, остатки, отчёты «Выработка» и «Табель»; может закрыть забытую смену сотрудника с указанием причины |
| **Сборщик зеркал** | Начать/закончить смену; видеть свои задачи на сегодня с прогрессом; «Сделал зеркало» (печать этикеток и скан приёмки своих зеркал); перепечатать этикетку своего зеркала в статусе «Напечатано»; смотреть остатки и карточку зеркала |
| **Грузчик** | Начать/закончить смену; **один рабочий экран — «Погрузка на паллету»** (скан ШК зеркала после укладки на паллету); видеть свои задачи на сегодня (текстовые). Больше ничего: остатки, журнал, печать ему недоступны |

Правила доступа:

- Без входа не открывается ни одна страница, кроме `/login` и `/health`.
- Проверка роли — на **сервере** для каждого маршрута (декоратор/зависимость), а не только скрытием кнопок. Запрос к чужому маршруту → 403 и понятная страница.
- Сборщик и грузчик **не могут выполнять сканирующие операции без открытой смены** (сервер отвечает отказом «Сначала начните смену»). Начальник смены и администратор работают без этого ограничения, но могут тоже отмечать смену.
- Первый администратор создаётся командой `python -m app.cli create-admin`.

### Вход

- Экран входа: выбор сотрудника из списка активных (поиск по имени) + PIN 4–6 цифр.
- 5 неверных PIN подряд → блокировка входа этому сотруднику на 15 минут (счётчик в БД, не в памяти).
- Сессия живёт 14 часов, затем повторный вход. Кнопка «Выйти» всегда видна.
- После входа сотрудник попадает на **свою главную**: сборщик — «Мой день» (смена + задачи), грузчик — «Мой день» с одной большой кнопкой «Погрузка», начальник смены — «Табло смены», админ — «Табло смены» + меню «Настройки».

## 5. Смены: «Начать смену» только по скану кода в цеху

### 5.1. Код смены

- Для каждой площадки сервер генерирует **код смены**: случайный секрет (32 байта, base64url). В QR кодируется строка вида `SHIFT:<site_id>:<секрет>`.
- Администратор на странице «Площадки» видит кнопку **«Распечатать код смены»** → PDF A4 с крупным QR, названием площадки и подписью «Скан для начала смены». Этот лист вешается в цеху.
- Кнопка **«Перевыпустить код»** создаёт новый секрет; старый сразу перестаёт работать (на случай, если код сфотографировали и унесли). Перевыпуск пишется в журнал администрирования.
- В БД хранится только хеш секрета (сравнение через `hmac.compare_digest`).

### 5.2. Начало смены

1. На экране «Мой день» кнопка **«Начать смену»**. Нажатие **не начинает смену сразу**, а открывает камеру телефона.
2. Сотрудник наводит камеру на QR в цеху. Ввод кода **только через камеру**: на этом экране нет текстового поля, и скан с клавиатурного сканера сюда не принимается.
3. Сервер проверяет код: верный секрет, площадка активна, у сотрудника нет уже открытой смены. При успехе создаётся смена (`started_at`, площадка из кода), экран становится зелёным: «Смена начата 08:02, Коминтерна». Площадка смены становится текущей площадкой сотрудника для всех операций.
4. При ошибке — красный экран с причиной: «Код не распознан», «Код устарел — обратитесь к администратору», «Смена уже начата в 08:02».

### 5.3. Дополнительная защита (настройка площадки, по умолчанию выключена)

- **Проверка геолокации:** у площадки можно задать координаты и радиус (по умолчанию 300 м). Если включено, при начале смены браузер запрашивает геопозицию; вне радиуса или при отказе дать доступ — смена не начинается, причина показывается на экране. Координаты сотрудника сохраняются в записи смены.
- Записать в смену IP и User-Agent устройства в любом случае — для разбора спорных случаев.

В `DECISIONS.md` честно отметить: статичный QR можно сфотографировать, поэтому предусмотрены перевыпуск кода и геолокация.

### 5.4. Окончание смены

- Кнопка **«Закончить смену»** — тоже через скан того же кода площадки камерой (чтобы нельзя было закрыть смену из дома и «добавить» часы). Записывает `ended_at`.
- Если смена не закрыта до 23:59 по Москве, в 00:05 она закрывается автоматически с пометкой «не закрыта сотрудником»; время окончания — время последнего скана сотрудника в эту смену (или время начала, если сканов не было).
- Начальник смены может вручную закрыть или поправить время смены с обязательным комментарием; правка пишется в журнал, исходные значения сохраняются.

### 5.5. Табло «Кто на смене» (начальник смены, админ)

- Список всех активных сборщиков и грузчиков по выбранной площадке на сегодня: **на смене** (с какого времени), **смена закончена** (с—по), **не вышел**.
- У каждого на смене — сколько зеркал принято/отгружено за смену и прогресс по задачам.
- Обновление раз в 30 секунд без перезагрузки страницы.

### 5.6. Отчёт «Табель»

Период (по умолчанию текущий месяц) × сотрудник: по дням время начала, окончания, длительность, отметка «закрыта автоматически/вручную». Итог часов за период. Выгрузка в CSV (UTF-8 с BOM, разделитель `;` — чтобы открывалось в Excel).

## 6. Сценарии работы со складом

Во всех сценариях сканирования после скана экран **сразу** показывает результат: **зелёный** с артикулом и новым остатком или **красный** с причиной отказа, плюс короткий звуковой сигнал (разный для успеха и ошибки, через Web Audio API, без файлов). Поле скана после ответа очищается и снова в фокусе. Справа/снизу — последние 10 сканов этой сессии.

Каждый экран сканирования принимает ввод и со сканера-клавиатуры, и через кнопку **«Сканировать камерой»**.

Распознавание своей этикетки: строка совпадает с регулярным выражением `^(Z|A|AT|X)\d{7}$` (после `strip()` и приведения к верхнему регистру). Всё остальное — ШК маркетплейса или чужой код.

### 6.1. «Мой день» — задачи сборщика

Это первый экран сборщика после входа.

- Сверху — блок смены: «Смена не начата» + кнопка «Начать смену», или «На смене с 08:02 · Коминтерна» + «Закончить смену».
- Ниже — **«Задачи на сегодня»**: список задач, поставленных этому сборщику на сегодняшнюю дату. Для задачи-артикула: артикул, план, **сделано** и полоса прогресса; задача выполнена, когда сделано ≥ план (зелёная галочка). Для текстовой задачи — текст и кнопка «Готово».
- **«Сделано» считается автоматически**: число зеркал этого артикула, где сборщик = этот сотрудник и переход `printed → in_stock` произошёл сегодня (по Москве), за вычетом тех, что сегодня же списаны как брак. Вручную не вводится.
- Нажатие на задачу-артикул открывает «Сделал зеркало» с уже выбранным артикулом.
- Если задач нет — «На сегодня задач нет, уточните у начальника смены».

### 6.2. Постановка задач (начальник смены)

- Экран **«Задачи»**: выбор даты (по умолчанию **завтра**) и площадки. Таблица: сотрудник × задачи.
- Добавить задачу сборщику: артикул (поиск по части названия, нормализованный — см. 9) + количество; или текстовое поручение. Грузчику — только текстовое поручение.
- Кнопка **«Скопировать задачи с сегодняшнего дня»** — переносит невыполненный остаток плана (план − сделано) на выбранную дату.
- Задачи на сегодня и будущие даты можно править и удалять; прошедшие — только просматривать. Все изменения задач пишутся в отдельный журнал задач (кто, когда, что было → что стало).
- Отчёт по задачам за период: план / факт по сотрудникам и артикулам.

### 6.3. Изготовление и печать этикетки («Сделал зеркало»)

1. Сборщик выбирает артикул (поиск по части названия или из своей задачи) и количество (1–50).
2. Нажимает **«Печать»**. Сервер в одной транзакции получает номера из sequence, создаёт зеркала в статусе «Напечатано» (сборщик = вошедший сотрудник, площадка = площадка текущей смены) и отдаёт PDF с этикетками; PDF открывается в новой вкладке для печати.
3. Сборщик клеит этикетку на упаковку и сканирует её в поле на этом же экране → `in_stock`, остаток +1, прогресс задачи обновляется.

Правила:
- Повторный скан принятого зеркала → отказ «Уже на складе (принято 10.10 в 14:20)».
- Сборщик может принимать только свои зеркала; начальник смены — любые.
- Начальник смены на этом экране дополнительно выбирает сборщика из списка (зеркала записываются на выбранного сборщика, а действие — на начальника).
- Этикетки в статусе «Напечатано» старше суток — отдельный список у начальника смены («принять» или «списать»).
- Перепечатка испорченной этикетки — тот же номер, новый номер не выдаётся.
- Сборщик зеркала хранится навсегда; изменить может только начальник смены/админ с записью в журнал.

### 6.4. Погрузка на паллету (грузчик) — отгрузка

Единственный рабочий экран грузчика. Крупные элементы, ничего лишнего.

1. Грузчик выбирает канал: **Ozon / WB / СДЭК** и нажимает **«Новая паллета»** — создаётся паллета с номером (`P` + дата + порядковый, напр. `P20261013-03`) и площадкой смены. Если у грузчика уже есть открытая паллета — продолжает её.
2. После укладки каждого зеркала на паллету грузчик **сканирует ШК зеркала** → статус `shipped`, зеркало привязывается к паллете и каналу, остаток −1. Экран: зелёный, артикул, «На паллете: 17».
3. **Необязательно (этап 1) / обязательно (этап 3, переключатель в настройках):** сразу после ШК зеркала сканируется ШК маркетплейса, наклеенный на это зеркало; он привязывается к зеркалу.
4. Кнопка **«Закрыть паллету»** → итог: количество по артикулам. Закрытую паллету нельзя дополнить.

Правила:
- Зеркало не в статусе `in_stock` → отказ с текущим статусом: «Уже отгружено 08.10 в 14:20, паллета P20261008-02».
- Зеркало на другой площадке → отказ «Зеркало числится на Учительской».
- Один ШК маркетплейса нельзя привязать к двум зеркалам (уникальный индекс в БД).
- Если отсканирован ШК маркетплейса, когда ожидается ШК зеркала → отказ «Это код маркетплейса, сначала отсканируйте этикетку СКЛАД».
- **Этап 3:** при включённой сверке система ищет ШК маркетплейса в списке отправлений, переданном из BLAGO OTGRUZKI, и сравнивает артикулы (после нормализации). Не совпало → отказ «Зеркало Zerkalo_60x160, а заказ на Zerkalo_60x170», зеркало остаётся на складе.
- Начальник смены может отменить ошибочную отгрузку последних 10 минут — это новое движение `shipped → in_stock` с типом `ship_cancel`, а не удаление.

### 6.5. Перемещение между площадками (начальник смены)

1. Площадка-отправитель: экран «Перемещение», выбор площадки-получателя, скан каждого зеркала → `in_transit`, остаток отправителя −1.
2. Площадка-получатель: экран «Приёмка перемещения», скан → `in_stock` на новой площадке.
- Зеркала в пути больше суток — отдельный список.

### 6.6. Инвентаризация (начальник смены)

1. Начать инвентаризацию площадки целиком или группы артикулов. Одновременно на площадке может идти только одна.
2. Сканировать все зеркала, физически лежащие на складе. Повторный скан того же зеркала в этой инвентаризации — без ошибки, просто «уже учтено».
3. Система показывает два списка: «по учёту есть, не отсканировано» и «отсканировано, по учёту не на складе».
4. Подтверждение: первые → `written_off`, вторые → `in_stock` на этой площадке. Каждое исправление — движение `inventory_fix` со ссылкой на инвентаризацию.
- Пока идёт инвентаризация, отгрузки и перемещения на этой площадке разрешены, но зеркала, прошедшие через них после старта, исключаются из расхождений (сравнение по времени движений).

### 6.7. Брак и возврат (начальник смены)

- **Списание:** скан + причина из списка (брак, бой, потеря, ошибочная этикетка, другое + комментарий) → `written_off`.
- **Возврат:** скан + «годное / негодное». Годное → `in_stock` на текущей площадке, негодное → `written_off`.

### 6.8. Карточка зеркала (все, кроме грузчика)

По номеру или скану: артикул, статус, площадка, сборщик, дата изготовления, канал, паллета, ШК маркетплейса, полная история движений. Кнопки по роли: «Перепечатать этикетку», «Изменить сборщика», «Списать».

### 6.9. Остатки — в том же виде, что в гугл-таблице

Отгрузки владелец ведёт в гугл-таблице и переносит туда данные из системы. Поэтому экран «Остатки» должен **повторять левый блок гугл-таблицы «ДО отгрузок»** так, чтобы строки совпадали один в один и данные можно было вставить без сдвигов. Сборщик и начальник смены видят экран, грузчик — нет.

**Порядок и состав строк**
- Строки идут **ровно в том порядке, что в TOP.xlsx**: сначала лист «Полотна», затем «Алюминий», затем «Безрамные». Внутри листа — сверху вниз, как в файле (`sort_order` из импорта). Никакой сортировки по алфавиту или остатку.
- Строки-заголовки подгрупп выводятся отдельными строками на всю ширину, жирным: «Полотна», «Полотна без креплений», «АЛЮМИНИЙ», «АЛЮМИНИЙ на ноге», «БЕЗРАМНЫЕ с подсветкой», «БЕЗРАМНЫЕ КРУГЛЫЕ» и т.д. Как в таблице, это не артикулы.
- Неактивные артикулы по умолчанию **не скрываются**: строка остаётся на месте с остатком 0, иначе съедет порядок при вставке. Скрыть их можно отдельным флажком, который на копирование не влияет.
- Артикул выводится в исходном написании из TOP (с кириллической «х», если она там есть), не в нормализованном.

**Столбцы** (как в таблице, слева направо):

| Артикул | Учительская | Коминтерна | Задачи на Учительской | Задачи на Коминтерна |
|---|---|---|---|---|

- Остатки — количество в статусе «На складе» на площадке **на текущий момент**.
- «Задачи на …» — сумма `qty_plan` задач-артикулов на выбранную дату по площадке (по умолчанию — **сегодня**; переключатель даты над таблицей, рядом дата в шапке, как «13.10» в таблице). Пусто, если задач нет (не 0 — как в таблице).
- Столбцы площадок строятся по списку активных площадок; порядок площадок задаёт админ (по умолчанию Учительская, Коминтерна — как в таблице).
- Вверху закреплённая шапка, первый столбец закреплён при горизонтальной прокрутке.

**Цвета** (как в таблице)
- Ячейка остатка = 0 — розово-красный фон; < 0 невозможно (остаток не бывает отрицательным).
- Фон строк — цвет подгруппы. При импорте TOP.xlsx брать заливку ячейки артикула (RGB; если в файле цвет темы — взять ближайший из палитры по умолчанию). Админ может поменять цвет подгруппы в «Настройки → Артикулы». Палитра по умолчанию: полотна — `#FFE0C1`/коричнево-оранжевые оттенки, алюминий black — `#DCE0F8`, алюминий на ноге — `#FFE5E5`, Ambient 4000 — `#B7E1CD`, Ambient 3000 — голубой, Ambient 6000 — оранжевый, gorizont/vert — `#DEEFA0`.
- Шрифт и плотность — компактные, как в таблице (на ноутбуке видно 40+ строк без прокрутки); на телефоне — та же таблица с горизонтальной прокруткой.

**Перенос в гугл-таблицу — три способа, все обязательны**
1. **Кнопки «Копировать столбец»** над каждым числовым столбцом и **«Копировать Учительская + Коминтерна»** (два столбца рядом). В буфер кладётся текст в формате TSV: одно значение на строку, **строго в порядке строк таблицы, включая пустые значения на месте строк-заголовков подгрупп**, чтобы после вставки в ячейку C4 гугл-таблицы всё легло ровно напротив своих артикулов. Пустые задачи — пустая строка, не 0. После копирования — всплывающее «Скопировано 306 строк».
2. **Кнопка «Скачать CSV/XLSX»** — тот же вид, те же строки, те же цвета (в XLSX), имя файла `Остатки_13.10.2026_14-20.xlsx`.
3. **Автовыгрузка раз в 5 минут** на лист «Остатки из системы» (раздел 10) — для формул.

Над таблицей — время последнего обновления и кнопка «Обновить»; данные на экране — на момент загрузки, без автообновления, чтобы цифры не менялись под рукой во время копирования.

**Блок «ПОСЛЕ отгрузок» в системе не делается**: отгрузки по каналам (OZON утро, КГТ, СДЭК, WB Тверь, ТВ СГТ, Озон 2…) и расчёт «склад − отгрузка», «склад + задачи − отгрузки» остаются в гугл-таблице.

### 6.10. Журнал и отчёты (начальник смены, админ)

- Журнал движений с фильтрами: дата, артикул, сотрудник, тип, площадка, номер зеркала. Пагинация. Экспорт CSV.
- **«Выработка»**: по каждому сборщику за период — сделано зеркал по артикулам, из них списано в брак, % брака.
- **«Табель»** (раздел 5.6) и **«Задачи план/факт»** (раздел 6.2).

### 6.11. Первый запуск

Перед запуском площадка пересчитывается, на весь остаток печатаются этикетки через 6.3 (начальник смены выбирает сборщика «Остаток на запуск» — служебный сотрудник, создаётся миграцией) и наклеиваются. На экране «Остатки» до отметки администратора «Маркировка завершена» показывается плашка «Остатки площадки ещё не достоверны».

## 7. Штрихкод и этикетка

**Формат номера:** префикс группы + 7 цифр.
- `Z` — артикулы, начинающиеся с `Zerkalo` или `bp_Zerkalo`; `A` — `Alum`; `AT` — `Ambient`; `X` — всё остальное. Определяется функцией по нормализованному артикулу, покрыть тестами.
- Цифры — из **одной общей** sequence PostgreSQL, номера не повторяются и не переиспользуются, независимо от префикса и площадки.
- Полный артикул в штрихкод не вшивается — находится по номеру в БД.

**Этикетка** (по образцу из приложенного PDF):
- Чёрная шапка: белым «СКЛАД» слева и название площадки справа.
- Артикул крупным жирным текстом, переносится на 2 строки, автоуменьшение шрифта, чтобы влез.
- Штрихкод Code 128 с номером, номер цифрами под ним.
- Внизу мелко: «Сборщик: Иван · 10.10.2026».
- PDF: одна этикетка на страницу, размер по умолчанию **58 × 40 мм**, меняется в настройках (ширина и высота в мм). Печать — обычным диалогом браузера на термопринтер.
- Проверить тестом, что штрихкод из сгенерированного PDF читается (растеризовать страницу и распознать `pyzbar`/`zxing-cpp` в тесте).

**QR кода смены** — отдельный PDF A4 (раздел 5.1).

Жёсткие правила:
- **Статус зеркала меняется только вместе с записью в `movements`, в одной транзакции.** Реализуй одну функцию `apply_transition(unit, to_status, ...)`, через которую идут все изменения статуса; прямое присваивание `unit.status` где-либо ещё запрещено (проверить grep-тестом).
- Защита от гонок: при скане строка зеркала блокируется `SELECT ... FOR UPDATE`; два одновременных скана одного зеркала → ровно один успех.
- Не больше одной открытой смены на сотрудника — частичный уникальный индекс `WHERE ended_at IS NULL`.
- Не больше одной открытой паллеты на грузчика, одной активной инвентаризации на площадку — частичные уникальные индексы.
- Записи `movements` не удаляются и не редактируются (на уровне БД: триггер, запрещающий UPDATE/DELETE).
- Остаток = `COUNT(*) FROM units WHERE status='in_stock' GROUP BY article_id, site_id`. Индекс `(status, site_id, article_id)`.
- Должна существовать команда `python -m app.cli verify-stock`, которая пересчитывает остатки из журнала движений и сравнивает с таблицей `units`; при расхождении — ненулевой код выхода.

## 9. Импорт справочника из TOP.xlsx

Структура файла (проверь на приложенном файле):
- Листы **«Полотна»**, **«Алюминий»**, **«Безрамные»** = группа.
- Строка 2 — заголовки; артикулы в столбце A с 3-й строки.
- Строки, где текст в A целиком ЗАГЛАВНЫМИ (`ПОЛОТНА`, `БЕЗРАМНЫЕ КРУГЛЫЕ`, …), — это заголовки подгрупп, не артикулы.
- В столбце B иногда стоит подпись подгруппы (`полотна без креплений`, `алюминий на ноге`) — она действует на эту строку и все ниже до следующей подписи/заголовка.
- Пустые строки пропускаются; дубли (после нормализации) — одна запись + предупреждение в отчёте импорта.

**Нормализация артикула** (`normalize_article`): `strip()`, схлопнуть повторные пробелы в один, кириллическая «х»/«Х» между цифрами и в размерах → латинская `x`, сравнение без учёта регистра. В TOP есть смешанные `100х200` (кириллица) и `80x200` (латиница) — после нормализации это одно правило. Показывается артикул в исходном написании.

Импорт: загрузка файла на странице «Настройки → Артикулы» и CLI `python -m app.cli import-top TOP.xlsx`. Повторный импорт не создаёт дублей, новые артикулы добавляет, отсутствующие **не удаляет** (можно деактивировать вручную). После импорта — отчёт: добавлено / уже было / дубли / пропущено.

## 10. Интеграции

- **Google Sheets:** раз в 5 минут сервер перезаписывает лист «Остатки из системы» (создаёт, если его нет). Содержимое — **те же строки и в том же порядке, что на экране «Остатки»** (раздел 6.9), включая строки-заголовки подгрупп:
  `A: Артикул (как в TOP) | B: Учительская | C: Коминтерна | D: Задачи на Учительской | E: Задачи на Коминтерна`, в ячейке G1 — «Обновлено: 13.10.2026 14:20».
  Перезаписывается только этот лист, остальная таблица не трогается. Запись одним запросом (`batch_update`/`update` диапазона), чтобы лист не был наполовину пустым во время обновления.
  В README привести готовые формулы для основного листа, по имени артикула (не зависят от порядка строк):
  `=ЕСЛИОШИБКА(ВПР($B4;'Остатки из системы'!$A:$E;2;0);"")` — Учительская,
  `=ЕСЛИОШИБКА(ВПР($B4;'Остатки из системы'!$A:$E;3;0);"")` — Коминтерна, и аналогично 4 и 5 для задач.
  Поскольку артикул выгружается в исходном написании из TOP, ВПР находит его даже при смешанных «х»/«x».
  Кнопка «Выгрузить сейчас» у админа и начальника смены. ID таблицы и JSON сервисного аккаунта — из env. Ошибки не роняют приложение, а пишутся в лог и показываются на странице «Состояние» и плашкой на экране «Остатки» («Гугл-таблица не обновлялась 25 минут»).
- **API для BLAGO OTGRUZKI** (ключ в заголовке `X-API-Key`, ключи создаёт админ, хранится хеш):
  - `GET /api/v1/stock` — остатки: `[{article, site, qty}]`.
  - `POST /api/v1/shipments` — приём списка отправлений дня `[{mp_barcode, article, date}]`, идемпотентно (upsert по `mp_barcode`).
  - OpenAPI-документация по `/docs` доступна только админу.

## 11. Требования к интерфейсу и надёжности

- Ответ на скан ≤ 1 с при обычном мобильном интернете: один запрос, без лишних запросов к БД (проверить тестом количество SQL-запросов на скан).
- **Нет связи:** если запрос скана не дошёл/упал по таймауту (5 с) — красный экран «Нет связи, скан НЕ записан». Сканы **не копятся** на устройстве и не отправляются позже. Повторная отправка того же скана после восстановления связи безопасна (идемпотентность по номеру + целевому статусу).
- Кнопки и поля не меньше 48 px, основной шрифт ≥ 18 px, контраст достаточный для цеха. Работает в Chrome на Android и в Safari на iPhone (камера требует HTTPS — в dev-режиме используй `localhost`).
- Все тексты интерфейса на русском. Даты в формате `13.10.2026 14:20`.
- Ошибки сервера (500) не показывают трассировку; пишутся в лог с идентификатором, пользователь видит «Ошибка, код 7f3a… — сообщите администратору».
- Логи в JSON в stdout.

## 12. Обязательные автотесты

Каждый пункт — отдельный тест (или группа), все зелёные:

1. Все 8 разрешённых переходов работают; каждый неразрешённый переход отклоняется с понятным текстом.
2. Двойной скан одной этикетки не меняет остаток второй раз.
3. Два одновременных скана одного зеркала (два потока/соединения) → ровно одна запись в журнале.
4. Два сотрудника одновременно печатают по 20 этикеток → 40 разных номеров, без пропусков внутри каждой пачки не требуется, но без повторов — обязательно.
5. Остаток, посчитанный по `units`, равен остатку, восстановленному по `movements` (на случайной последовательности из 1000 операций — property-based тест через `hypothesis`).
6. Один ШК маркетплейса нельзя привязать к двум зеркалам.
7. Сверка с заказом (этап 3): несовпадение артикула → отказ, зеркало остаётся `in_stock`.
8. Нормализация: `Zerkalo_100х200` (кириллица) == `Zerkalo_100x200`; лишние пробелы; префиксы `Z`/`A`/`AT`/`X`, включая `bp_Zerkalo…` → `Z`, `Ambient…` → `AT` (не `A`!).
9. Импорт приложенного `TOP.xlsx`: ожидаемое число артикулов, подгруппы проставлены, заголовки не попали в артикулы, повторный импорт ничего не дублирует.
10. Роли: для каждого маршрута проверено, что запрещённые роли получают 403 (параметризованный тест по таблице «маршрут → разрешённые роли»).
11. Сборщик/грузчик без открытой смены не может сканировать.
12. Смена: неверный код → отказ; код площадки после перевыпуска → отказ; вторая открытая смена невозможна; геопроверка вне радиуса → отказ; автозакрытие в 00:05 ставит правильное время.
13. Задачи: «сделано» считается только по зеркалам этого сборщика, этого артикула, принятым сегодня по Москве (проверить на границе суток 23:59/00:01 МСК); копирование невыполненного остатка на завтра.
14. Блокировка входа после 5 неверных PIN и разблокировка через 15 минут.
15. Штрихкод из PDF этикетки распознаётся и равен номеру.
16. Попытка UPDATE/DELETE в `movements` падает на уровне БД.
17. CSRF: POST без токена отклоняется.
18. `verify-stock` возвращает 0 на согласованной БД и ≠0 после ручной порчи данных.
19. Экран «Остатки»: порядок строк совпадает с порядком в `TOP.xlsx` (включая заголовки подгрупп); TSV из «Копировать столбец» содержит ровно столько строк, сколько строк в таблице от первого артикула до последнего, с пустыми значениями на месте заголовков; лист «Остатки из системы» совпадает построчно с экраном.
20. Задачи на экране «Остатки» = сумма плана по площадке и дате; пусто, если задач нет.

Плюс один сквозной тест браузером (Playwright): вход сборщика → начало смены (камера подменяется вызовом того же обработчика с кодом) → задача видна → печать → скан → прогресс задачи 1/N → вход грузчика → паллета → скан → остаток 0.
